# Reference Implementations

Validation targets, NOT distributable products. These exist to demonstrate that
the binding ontology, design system, and platform ontology operationalize
together.

Contents change to match the latest binding/ontology state. Reference
implementations may be torn down and regenerated when the underlying ontology
shifts.

- `axismundi-lab/` — component and WordPress-block binding catalogue. Read
  before implementing a component; it is the design and binding baseline the
  shipped products are checked against.

The two theme pilots that used to live here (`axismundi-pilot`,
`ontology-theme-pilot`) were removed once the shipped theme stopped deriving
from them. Their history is in git.

For installable, semver-versioned products, see `../wordpress/`.
