# Brief — 원격 Object 를 **어느 Actor 의 권한으로** 가져올 것인가

> **범위**: 홈 서버가 선택된 Actor 의 키로 원격 Object 를 서명 GET 하는 경로. 그 권한 판정과
> 캐시 계약까지. GUI 와 익명 열람은 이 슬라이스가 아니다.
> 이웃: [C2S.md](C2S.md) · AP Session(`includes/c2s-session.php`) ·
> OP 의 원격 캐시(`axismundi-object-projections/includes/remote-objects.php`)

## 메우려는 공백

ActivityPub 에 **"이 원격 URI 를 대신 조회해 달라"는 C2S 메서드가 없다.**

```txt
있다   §3.2 — Object 의 id 자체를 AS2 Accept 로 GET 한다.  원본 서버가 인증·접근제어를 걸 수 있다
       §7 도 같은 규칙을 쓴다 — Actor URI 를 GET 해 inbox 주소를 읽고 거기 POST 한다
없다   홈 서버에 "이 URI 의 캐시를 줘 / 없으면 가져와 줘 / 내 Actor 로 원본을 다시 읽어 줘"
       inbox·outbox 계약에 그 자리가 없다
우리    /axismundi/v1/objects/{id} 는 **내부 숫자 id** 로 읽는 애플리케이션 API 다.
       임의의 원격 URI 를 해결하는 경로가 아니다
```

AP Session 이 메우는 것은 **"누구로 요청할 수 있나"** 이고, 이 슬라이스가 메우는 것은
**"그 권한으로 홈 서버에 무엇을 가져와 달라고 할 수 있나"** 다. 연결되지만 같은 기능이 아니다.

## 가장 중요한 한 줄

**배달 서명은 역방향 조회 자격증명이 아니다.**

inbox POST 의 서명은 **발신자가 보낸 요청**을 검증한다. 그 POST 를 받았다는 사실이 수신자
Actor 의 권한으로 원본에 나가도 된다는 **위임이 아니다.** 그 위임은 지금 어디에도 없다.

```txt
따라서   **Inbox 수신만으로는 서명 GET 을 하지 않는다.**  이것이 계약이다
근거     "언제 가져올지의 정책" 이 아니라 **"누구의 권한으로 가져오는가"** 에 답이 없기 때문이다
위임의 출처  인증된 클라이언트가 **Actor 를 명시해** 열람을 요청하는 것.  그것이 신호다
```

## 수신 시점에 하는 일

```txt
본문이 실려 왔다      검증한 뒤 저장한다.  원본 GET 0회.
                   읽을 때 **요청 Actor 에게 내줘도 되는지는 따로 판정**한다
URI 만 왔다          Activity 와 URI 만 저장한다.  가져오지 않는다
```

URI 만 온 상태를 캐시 테이블에 미리 예약하지 **않는다.** 측정: 원격 캐시 스키마가
`payload_json longtext NOT NULL`, `payload_hash char(64) NOT NULL` 이라 미조회 자리를 만들려면
가짜 `{}` 를 넣어야 한다. **첫 구현은 원장의 `object_uri` 자체를 미조회 참조로 쓴다.** 캐시
행은 본문을 실제로 받았을 때만 만든다. 자리를 예약할 이유가 생기면 그때 **`미조회` 와
`본문 있음` 을 명시적으로 구분**한다 — 둘을 같은 행으로 뭉개지 않는다.

## 열람 흐름

```txt
① 클라이언트 → 홈 서버   선택한 Actor URI + 조회할 Object URI
② 홈 서버              그 사용자에게 can_act_as(Actor) 가 있는지 확인
③ 홈 서버 → 원본        **그 Actor 의 키로 새 GET 을 서명**한다
④ 원본                팔로우·멘션 등 접근 조건을 **원본이** 판단한다
⑤ 홈 서버 → 클라이언트   그 결과를 그대로 돌려준다
```

```txt
금지   클라이언트의 인증 헤더나 서명을 원격에 **그대로 전달**하는 것.  새로 서명한다
금지   개인키를 데스크톱에 주는 것.  키는 홈 서버에 남는다
금지   **임의 URL 에 Actor 서명을 붙여 주는 범용 프록시.**  이름 붙은 동작만 연다
금지   AP Session 에 Actor 가 보인다는 이유로 서명 조회 권한을 주는 것.
       지금 Session 은 **outbox 제출 가능 여부**를 말한다.  서명 조회는 별도 동작이다
```

## 캐시 — 본문 보유와 열람 허가는 다르다

```txt
본문은 URI 당 한 벌로 저장해도 된다
공유하면 안 되는 것은 **"이 본문을 읽어도 된다" 는 판정**이다
A 의 서명 GET 이 받은 200 은 **A 에 대한 결과**다.  B 나 같은 WordPress 로그인 전체에 대한
허가가 아니다
```

```txt
유효한 캐시가 있다       그 Actor 가 읽을 수 있으면 원본에 다시 요청하지 않는다
만료                  다음 열람 때 재조회한다
검증된 Update 수신      본문이 실려 있으면 GET 없이 갱신할 수 있다.
                     URI 만 오면 다음 열람 때 재조회한다
                     **본문 갱신만으로 열람 대상을 넓히지 않는다**
원본이 거부            **이전 본문을 대신 내주지 않는다.**  거부를 거부로 돌려준다
```

마지막 줄이 이 슬라이스에서 가장 틀리기 쉬운 자리다. 캐시를 대신 보여주면서 원본 조회
성공으로 처리하면, 사용자는 지금 읽을 권한이 있다고 믿게 된다.

## 감사 — 캐시가 **찬 뒤**가 본론이다

같은 URI 에 대해 `A`(팔로워 또는 실제 수신 대상)와 `B`(권한 없음)를 두고, **둘을 같은
WordPress 사용자가 운영**하게 한다. 그래야 Account 와 Actor 를 혼동하는 버그까지 잡힌다.

```txt
① URI 만 있는 Create 수신        원본 GET **0회**
② A 로 처음 열기                 **A 의 서명으로 GET 1회**, 본문 반환
③ A 로 다시 열기                 **추가 GET 없이** 캐시 반환
④ B 로 같은 URI 열기             **캐시가 있어도 본문을 받지 못한다**
⑤ 만료 후 원본이 A 를 거부        **이전 본문을 대신 내주지 않는다**
```

```txt
세는 것   원본 GET **횟수**를 센다.  "되더라" 가 아니라 몇 번 나갔는지가 ①③의 전부다
변이     can_act_as 검사를 지우면 ④가 실패해야 한다.
        캐시 반환 조건에서 Actor 판정을 빼면 ④가 실패해야 한다.
        거부 시 캐시 폴백을 넣으면 ⑤가 실패해야 한다
```

**④가 핵심이다.** 그 자리가 비면 "URI 당 본문 한 벌" 이 곧 "누구나 읽어도 된다" 가 된다.

## 발행 측 불변식 — 주소를 Object 에서 가져온다

조회 정책의 입력이 흔들리지 않게, 우리가 발행하는 활동의 주소를 Object 에 맞춘다.

```txt
Create   발행 직전 저장된 Object 의 주소를 Create 에 반영한다.
         §6.2.1 도 단독 Object 를 감쌀 때 주소 속성을 **Object → 활동** 방향으로 복사하게 한다.
         참조형 Create 에서는 **반대 방향으로 Object 를 고치지 않는다** (FEP-c3ab 규칙 1)
Update   주소를 바꾸지 않는 편집이면 기존 Object 의 주소를 쓴다.
         가시성 변경은 별도 정책이다 — 대상을 줄였다고 **이전 수신자의 캐시가 회수되지 않는다**
```

```txt
금지   원격에서 받은 활동과 Object 의 주소가 다르다고 둘을 합쳐 공개 범위를 넓히는 것
금지   수신 사실만으로 GET 권한을 추정하는 것
위치    주소는 배달과 조회 정책의 **입력**이지, 서명 GET 의 위임도 캐시 열람 허가도 아니다
```

## 없는 것 — 먼저 만들어야 한다

```txt
서명 GET 엔드포인트   **없다.**  AP Session 은 Actor 발견까지다.
                   Mastodon 이 그런 요청을 존중한다는 것은 소스로 확인했고
                   (signature_authentication.rb · status_policy.rb),
                   **우리 쪽 엔드포인트는 구현되지 않았다**
상호운용 전제        원본이 서명 GET 으로 제한 공개를 내준다는 것은 **Mastodon 의 규칙**이다.
                   모든 구현이 같다고 가정하지 않는다.  거부도 정상 결과다
```
